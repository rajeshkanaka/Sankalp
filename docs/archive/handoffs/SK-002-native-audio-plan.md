## Supported evidence route

Apple documents **VO-Shift-Z** as exporting the last phrase spoken by VoiceOver to an audio file in a Desktop archive folder. That folder also contains diagnostic logs. **VO** is Control-Option by default, or Caps Lock with the default alternate modifier. This gives a route to actual VoiceOver output even if the caption overlay is absent from an app screenshot. A created file alone is insufficient: listen to the exported utterance and compare it with the deliberately focused synthetic control or triggered application status. [Apple: last spoken phrase](https://support.apple.com/en-au/guide/voiceover/vo2725/mac), verified 2026-09-06.

The caption panel displays VoiceOver's spoken output. It can be enabled in VoiceOver Utility → Visuals → Panels and Menus. Apple's documented Utility shortcut is VO-Fn-F8 and its caption toggle is VO-Fn-Command-F10. Prefer the observed setting over an unverified toggle; do not change braille or other visual preferences. [Apple: caption panel](https://support.apple.com/guide/voiceover/use-the-braille-and-caption-panel-unac078/mac), verified 2026-09-06.

The current supported native CUA API exposes app accessibility state, app screenshots, native key presses, clicks, and text entry. It does **not** expose direct system-audio recording or a full-desktop screenshot endpoint. Use only the CUA APIs actually documented in the active session; do not revive the previous retry's `@oai/sky` route, use shell UI automation, or treat a voice-chat-only screen tool as available in a text session. A browser-extension tab may be unavailable in Guest mode; the native app surface is the planned control route.

An accessibility tree can establish a role, accessible name, focus, or state. It cannot establish that VoiceOver announced that information. Generated speech from tree text is also not VoiceOver evidence. Retain an observable caption or the actual exported utterance for each announcement claim, alongside the functional result.
