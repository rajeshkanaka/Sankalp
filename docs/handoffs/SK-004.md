## Implemented

- Added `generateScheduleRevision` as the single pure revision generator. It keeps the original calendar anchor, applies the effective-date floor, counts retained rows toward occurrence duration, preserves retained ordinals, allocates new ordinals after the retained maximum, reuses the existing timezone gap/fold resolution and overlap check, and rejects opened proposals, destructive duration reductions and zero-active calendar results.
- Added owner-authorized schedule preview/apply services. Preview takes a journey share lock and apply takes the journey lock followed by ordered active-session locks. Both classify from one server clock sample and build the same normalized fingerprint. Apply inserts an immutable version/practice snapshot, tombstones only the locked unopened eligible rows, verifies the guarded update set, inserts replacement sessions and zero values, advances the journey revision once, and returns the canonical view in the existing idempotent transaction.
- Added the separate metadata mutation. It changes only title, intention and the corresponding draft fields; schedule versions, practice definitions and sessions remain unchanged.
- Added `RevisionEditor` and `MetadataEditor` exports under `src/features/journeys/revision`. Revision input reuses the setup practice and schedule controls, explains the immutable original start and retained-history rule, holds a stable candidate between preview/apply, shows changed timestamps and requires an explicit apply action.
- Added pure unit coverage, guarded real-database integration coverage, and an `@M2-revisions` browser workflow. Integration cases cover opened identity/labels, tombstones, stable ordinals, idempotent retry/body reuse, opening-boundary invalidation, concurrent completion at the boundary, occurrence/calendar reductions, metadata isolation, stale revisions and owner-private 404 responses.
