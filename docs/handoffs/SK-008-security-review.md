## Actionable finding

**P2 — A stale sign-out action can sign out a newly selected account.** `src/components/app-shell.tsx:68` posts `{}` without an expected account, and `src/app/api/auth/sign-out/route.ts:9–13` calls `auth.signOut()` without checking the intended identity. The provider's preceding identity GET does not bind the later POST to that identity. Reproduction sequence: A finishes local purge; hold its verified identity response; B completes a real sign-in in another tab; release A's response; A's callback sends the sign-out POST with B's current cookies. The endpoint accepts it and signs out B. The pinned Supabase implementation defaults to global sign-out (`node_modules/@supabase/auth-js/src/GoTrueClient.ts:4054`), increasing the possible impact. This is established by the source execution path; the reviewer did not run the race.

Coordinator accepted the finding and assigned the endpoint/auth unit fix to the core worker, and the caller/layout plus actual browser race to the coordinator. Chosen fix: required validated accountId in the POST body, fresh same-client identity verification before sign-out, mismatch409, local sign-out scope, and existing authoritative401/response-loss recovery preserved. This report records the pre-fix finding; it does not claim the fix or its tests passed. Follow the coordinator's later integration evidence.

## Boundaries inspected without another concrete finding

Private HTML, APIs and RSC are never written to Cache Storage; navigation fallback occurs only after transport failure and returns the public shell. An online401/403/5xx is returned unchanged.
