## Implemented

- `savePractices`, `confirmSession` and the new `removeCompletion` execute under the existing
  owner-scoped transaction and journey/session locks. The single authoritative clock is sampled
  after those locks. Every successful mutation increments the session revision once and writes an
  amendment carrying that exact revision before the receipt is stored.
- A new operation ID with an unchanged value, performed time or already-removed completion returns
  `409 NO_CHANGE`; an exact retry returns its original receipt. Practice edits remain active-only,
  confirmed values require completion removal first, and archived session history remains readable.
- A closure event is captured once before any post-close change and during a locked history read.
  Its due-time status remains immutable while later value saves, confirmations, timing corrections
  and completion removal append factual correction events. Undo clears completion timestamps while
  retaining practice values and all history. Complete closure markers exist in storage but are
  intentionally hidden from the user timeline.
- `getSessionHistory` returns typed amendments and history events in recorded order. Database event
  payloads contain IDs, status/timing transitions and revision linkage; they do not copy practice
  labels, reflection text or practice values into notification history.
- `PracticePanel` accepts optional materialized `initialHistory`, permits saved-value corrections
  after closing, and presents explicit timezone-local actual-time entry. It distinguishes an
  in-window practice recorded later from a practice performed late, supports correcting the time,
  and requires a separate confirmation before removing completion.
- Failed practice and completion operations retain their exact operation envelope for safe retry.
  Revision conflicts retain local inputs. An owner-authorized `NO_CHANGE` response is accepted only
  after its unknown `current` value passes a narrow `SessionRecord` shape check. It then clears the
  acknowledged dirty/retry state; a practice acknowledgement preserves all other dirty local
  drafts. Time-correction and undo acknowledgements leave the panel usable.
- The visible timeline combines amendments with post-close correction events without duplicating
  event-linked amendments. It shows missed/partial closure and subsequent changes in real chronology
  while omitting the internal complete closure marker.
